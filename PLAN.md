# План работ по ПРУФ

## Принципы

1. Каждый этап заканчивается рабочим состоянием и пушем в репозиторий.
2. Ядро без внешних зависимостей: продукт должен ставиться в закрытый контур без интернета.
3. Всё, что показано в интерфейсе, считается настоящим движком, а не заглушкой. Там, где данные демонстрационные, это подписано в самом интерфейсе.
4. Любая цифра в документации воспроизводится командой из README.

## MVP за 12 недель (для питча)

| Недели | Что делаем |
| --- | --- |
| 1–3 | Песочница, прогон тестов, генератор мутаций |
| 4–5 | Сессия верификации: загрузка решения, таймер, вопросы, протокол PDF |
| 6–7 | Кабинет работодателя: вакансия, пул кандидатов, сравнение протоколов |
| 8 | Второй стек (JS или Java) |
| 9 | Интеграции: вебхук в HR-систему, экспорт CSV, LTI 1.3 для вузовского канала |
| 10–12 | Два платных пилота + один пилот в закрытом контуре |

## Риски и меры

| Риск | Мера |
| --- | --- |
| Кандидат воспринимает защиту как унижение | 15 минут, до собеседования, протокол остаётся у кандидата и переиспользуется |
| Узкий каталог мутаций не покрывает реальный код | Начинаем с тестовых заданий и стажёрских проектов, а не с легаси |
| «У нас уже есть техсобес» | Продаём не замену, а фильтр перед ним |
| Мутации не строятся для части языков | Текстовые шаблоны с обязательной проверкой компиляции |
