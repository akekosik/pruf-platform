Как устроен ПРУФ

Платформа доказывает, что человек понимает код, который принёс. Решение разбирается в AST, из него строятся 9–15 мутаций, тесты прогоняются в изолированной песочнице, а дальше идёт 15-минутная сессия защиты. На выходе — протокол понимания, а не зелёные тесты.

01

Быстрый старт

Внешних зависимостей нет. Нужен только Python 3.10+.

bash 
git clone https://github.com/akekosik/pruf-platform.git
cd pruf-platform
python3 -m engine.cli demo          # эталонный прогон ядра
python3 -m engine.cli serve --port 8000
# → http://127.0.0.1:8000
Открыть студию Демо-сессия защиты Кабинет работодателя

Песочница выполнения

Запуск чужого кода — главный риск платформы. Изоляция построена слоями.

СлойКак сделано
Процессpython -I -S
Файловая системаВременный каталог, удаляется после прогона
ОкружениеPYTHONHASHSEED=0
Времятаймаут 10 с, RLIMIT_CPU 5 с
ПамятьRLIMIT_AS 512 МБ
ИмпортыБлок-лист сети, процессов и системных вызовов
Канал результатаОдна JSON-строка после маркера __PRUF__

Честное ограничение: это изоляция уровня процесса. В продакшене слой заворачивается в контейнер с seccomp и сетевой политикой deny-all; интерфейс модуля не меняется.

05

Сессия защиты

Константы
  • Длительность — 900 секунд
  • Вопросов — от 6 до 15, по умолчанию 13
  • На одну мутацию — не больше 2 вопросов
  • Порядок вариантов — детерминированный сид
Четыре типа вопросов
  • danger — какая правка опасна (вес 1,2)
  • gap — какой тест поймает (вес 1,3)
  • first_failure — что упадёт первым
  • consequence — что будет на таком входе

В каждом вопросе есть две ловушки: «Ни один тест не заметит правку» и «Прогон упадёт целиком». Без них ответ угадывается методом исключения. Клиенту отдаётся проекция без правильных ответов — они не покидают сервер до завершения.

06

Протокол понимания

Главный артефакт продукта. Не оценка, а разбор по строкам и навыкам.

ПорогЗначениеСмысл
контролирует≥ 0,80Навык подтверждён
шатко≥ 0,50Знает, но плавает
не контролирует< 0,50Зона риска
Порог допуска70 %Настраивается компанией и печатается в протоколе

Восемь осей навыков: boundary, logic, arithmetic, strings, io, errors, collections, flow. Протокол выгружается в PDF и в текст — второй формат нужен для закрытого контура.

07

HTTP API

Базовый префикс /api. Ошибки — {"ok": false, "error": "…", "status": …}. Лимит тела запроса 400 КБ.

МетодМаршрутЧто делает
GET/api/healthСтатус, версия, число операторов
GET/api/catalog18 операторов мутаций
GET/api/tasksДемо-задания
GET/api/candidatesПул кандидатов
GET/api/candidates/<id>Карточка: сводка, протокол, анализ, код
GET/api/protocol/<id>[.pdf|.txt]Протокол в трёх форматах
GET/api/economicsЮнит-экономика и безубыточность
GET/api/demoПолный демо-прогон одним запросом
POST/api/mutations{code, limit} → превью мутаций без прогона
POST/api/run{code, tests} → прогон в песочнице
POST/api/analyze{code, tests, limit} → мутации + прогон + score
POST/api/session/startСоздаёт сессию защиты
POST/api/session/<id>/answerПринимает ответ
POST/api/session/<id>/finishЗавершает и собирает протокол
curl 
curl -s localhost:8000/api/health

curl -s localhost:8000/api/analyze \
  -H 'Content-Type: application/json' \
  -d '{"code": "def f(x):\n    return x > 0\n", "tests": "from solution import f\n\ndef test_f():\n    assert f(1)\n", "limit": 12}'

/api/analyze требует непустой code: на пустом теле вернётся ошибка 400 «Пустой код решения».

08

CLI

Не обёртка для удобства, а основной интерфейс для закрытого контура, где веб-сервер поднимать не разрешат.

engine.cli 
python3 -m engine.cli catalog
python3 -m engine.cli mutate solution.py --limit 12
python3 -m engine.cli run solution.py tests.py
python3 -m engine.cli analyze solution.py tests.py --limit 12
python3 -m engine.cli session solution.py tests.py
python3 -m engine.cli demo
python3 -m engine.cli economics
python3 -m engine.cli serve --port 8000

Автотесты ядра: python3 -m unittest discover -s tests -v

Цифры считаются ядром, а не зашиты в вёрстку.

Безубыточность — 800–900 верификаций в год, то есть 3–5 активных компаний при постоянных затратах ≈ 1,2 млн ₽. Сравнение «0 ₽ против 10,14 ₽ у LLM» относится к себестоимости и марже, а не к ценности для покупателя.

10

Вузы и Moodle

Мы не заменяем Moodle. Мы закрываем дыру, которую Moodle закрыть не может: он не умеет отличить понимание от сданного задания.

МеханизмРоль
LTI 1.3 AdvantageЗапуск проверки прямо из курса
AGSОценка возвращается в журнал курса
NRPSСостав группы подтягивается автоматически

Вуз не платит ничего: он поставщик трафика и данных для калибровки сложности. Внедрение идёт через приказ по кафедре, а не через закупку.

11

Приватность

Без прокторинга

Ни камеры, ни записи экрана, ни биометрии. Проверяется содержание, а не поведение.

Протокол — у кандидата

Он видит его целиком и переиспользует в других компаниях.

Нет вызовов LLM

Код кандидата не уходит во внешние модели и вообще за периметр.

Минимум данных

Для проверки нужны имя и код. Ни паспорта, ни селфи, ни телефона.

12

Частые вопросы

Вопросы строятся из конкретных строк конкретного решения и живут 15 минут. Чтобы списать, внешней модели нужно получить и код, и тесты, и мутации, и ответить быстрее человека — таймер и привязка к строке это ломают.
Это дыра в наборе тестов: правка меняет поведение, но ни один тест этого не заметил. Именно из таких мутаций получаются самые сильные вопросы.
Пересчётом. В протоколе есть отпечаток кода и команда воспроизведения: тот же набор мутаций строится заново и даёт тот же результат.
Да. Ядро не делает исходящих запросов и не вызывает LLM. Это условие для работы в закрытом контуре.
Нужен парсер с координатами узлов и отображение 18 операторов на конструкции языка. Где AST недоступен — текстовые шаблоны с обязательной проверкой компиляции.
