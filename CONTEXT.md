> Этот файл — страховка. Если сессия агента оборвётся, здесь достаточно информации, чтобы продолжить с того же места.
> Обновляется на каждом этапе. Последнее обновление: этап 2 (ядро проверено дымовым тестом).

## 1. Что это за продукт

**ПРУФ** — платформа верификации инженерных навыков для найма, стажировок и внутренних допусков.

Кандидат присылает решение (тестовое задание, учебный проект, кусок рабочего кода). Платформа:

1. разбирает решение в AST;
2. строит 9–15 мутаций **именно этого решения** (не абстрактных задач из банка);
3. прогоняет тесты в изолированной песочнице на оригинале и на каждом мутанте;
4. ведёт 15-минутную сессию защиты: какая правка сломает поведение, какая пройдёт незамеченной, где дыра в наборе тестов;
5. выдаёт **протокол понимания**: что человек контролирует, что шатко, что не контролирует.

Главный тезис: «зелёные тесты больше не доказывают, что человек понимает код».

### Почему это нельзя обойти ИИ

Вопросы строятся из конкретных строк конкретного решения и живут ровно одну сессию. Чтобы списать, внешней модели нужно получить код, тесты, мутации и ответить быстрее человека — таймер и привязка к строке это ломают. Прокторинга нет: ни камеры, ни экрана, ни биометрии. Проверяется содержание, а не поведение.

### Два аргумента, которых нет у конкурентов

- **Воспроизводимость**: любой спор разбирается пересчётом того же набора мутаций (детерминированный алгоритм, без LLM).
- **Работа без интернета и без LLM**: единственный способ зайти на режимные предприятия (ОПК, судостроение, БПЛА).

## 2. История: откуда взялся ПРУФ

Предыдущий проект — **СТАПЕЛЬ** (платформа микрообучения для вуза, акселератор СевГУ, задача №4). Оценка: инженерный прототип 9/10, бизнес 3/10.

Что было не так:

| Проблема | Суть |
| --- | --- |
| Плательщик | Кафедра вуза, 190 ₽ за студента в год. Пилот на 300 студентов = 57 000 ₽ выручки |
| Экономика | Пилот −9 272 ₽, год 1 −403 086 ₽, безубыточность на 3 745 студентах (2–3 вуза) |
| Moodle | Вуз видит дубль LMS, а не закрытие боли |
| Цикл закупки | Дольше гранта: от «понравилось кафедре» до платежа — учебный год или два |
| Аргумент «0 ₽ против 10,14 ₽ у LLM» | Это себестоимость, а не ценность для покупателя |

Решение: **механику оставить, плательщика поменять**. Отсюда ПРУФ.

Вузовский трек остаётся бесплатным каналом: встраивание в Moodle по LTI 1.3 Advantage (AGS — оценки в журнал, NRPS — состав групп), вуз не платит, он поставщик трафика и данных.

## 7. Архитектура репозитория

```
engine/        детерминированное ядро (Python 3.11+, только стандартная библиотека)
  mutations.py   AST-генератор мутаций, 18 операторов, 8 групп навыков
  sandbox.py     изолированный прогон тестов (отдельный процесс, лимиты CPU/RAM/FS, без сети)
  analysis.py    мутационный анализ: killed/survived, mutation score, дыры в тестах
  session.py     сессия защиты: 4 типа вопросов, детерминированная перетасовка, разбор ответа
  protocol.py    протокол понимания (JSON + PDF)
  store.py       файловое хранилище сессий и кандидатов
  fixtures.py    демо-данные: задачи, кандидаты, готовые протоколы
  economics.py   юнит-экономика и точка безубыточности
  cli.py         mutate / analyze / session / demo / serve
server/app.py  HTTP API на стандартной библиотеке + раздача статики
web/           прототип сайта без сборки и без CDN
docs/          документация по образцу СТАПЕЛЯ
tests/         автотесты (python3 -m unittest discover -s tests)
reports/       воспроизводимые JSON-отчёты
```

Зависимостей нет принципиально: продукт должен ставиться в закрытый контур.

## 8. Ключевые технические решения

1. **Мутация — это точечная замена фрагмента исходного текста** по координатам AST-узла (`lineno/col_offset/end_lineno/end_col_offset`), а не перегенерация файла через `ast.unparse`. Поэтому комментарии, форматирование и номера строк сохраняются байт в байт, и кандидат видит свой код, а не машинный.
2. `col_offset` в CPython — смещение в **байтах** UTF-8, поэтому срезы делаются по закодированной строке (важно для кириллицы в коде).
3. Каждый мутант компилируется перед запуском; невалидные отбрасываются. Дубликаты убираются по SHA-256 кода.
4. Разнообразие: отбор мутаций идёт по кругу по операторам (round-robin), чтобы 12 мутаций не оказались двенадцатью сдвигами констант.
5. Песочница: `python -I -S` в отдельном процессе, временный каталог, чистое окружение, `PYTHONHASHSEED=0`, RLIMIT_CPU / RLIMIT_AS / RLIMIT_FSIZE, блок-лист импортов (socket, subprocess, urllib, ctypes и т. д.), таймаут по часам родителя. Результат печатается маркером `__PRUF__` + JSON.
6. Кеш прогонов по SHA-256 (код + тесты + лимиты): повторный анализ того же решения мгновенный.
7. Вопросы сессии перетасовываются `random.Random(sha256(fingerprint + session_id + тип + id мутации))` — воспроизводимо и не угадывается.
8. Правильные ответы никогда не уходят клиенту: `session.public_view()` вырезает поле `correct` и разбор до момента ответа.

## 9. Словарь сущностей

- `SCHEMA_VERSION`: `pruf.mutations/1`, `pruf.sandbox/1`, `pruf.sandbox.run/1`, `pruf.analysis/1`, `pruf.session/1`.
- Навыки: `boundary`, `logic`, `arithmetic`, `strings`, `io`, `errors`, `collections`, `flow`.
- Операторы мутаций (18): CMP_BOUNDARY, CMP_EQUALITY, CMP_MEMBERSHIP, CMP_IDENTITY, BOOL_OP, NOT_DROP, ARITH_OP, DIV_KIND, AUG_OP, CONST_INT, CONST_BOOL, CONST_STR_IO, CALL_DROP_METHOD, CALL_SWAP_METHOD, SLICE_SHIFT, RANGE_BOUND, EXCEPT_SWALLOW, RETURN_DROP.
- Идентификаторы мутаций: `M01 … M15`.
- Типы вопросов: `danger` (какая правка опасна), `gap` (заметят ли тесты), `first_failure` (какой тест упадёт первым), `consequence` (что именно сломается).
- Вердикты по навыку: контролирует ≥ 0,80 · шатко ≥ 0,50 · не контролирует < 0,50.
- Порог подтверждённого понимания: 70 % взвешенных баллов.
