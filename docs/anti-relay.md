# АРП-2 «Оракул» — защита от релея через фотографию экрана

**Статус:** спецификация зафиксирована 15.09.2026 и является источником истины для `engine/arp.py`.
Прототип ядра по этой спецификации прогонялся локально: **30 из 33 проверок зелёные**, три расхождения — дефект самого сценария теста, а не протокола (раздел 11).
Сборочная песочница за сессию сбрасывалась пять раз и унесла локальную копию модуля, поэтому весь смысл протокола вынесен сюда: по этому документу ядро восстанавливается однозначно.

---

## 1. Модель угрозы: чем ломается первая версия

Атака в четыре шага, доступная любому кандидату:

1. открыть страницу проверки;
2. сфотографировать экран телефоном (или снять скриншот);
3. отдать кадр любой мультимодальной модели;
4. получить готовый ответ и нажать нужную кнопку.

Первая версия (АРП-1) была максимально уязвима: на экране показывался дифф правки и предлагалось выбрать, какой тест её поймает. И вопрос, и все варианты, и сам дифф находились **в одном кадре**, а значит ответ выводился из пикселей без единого обращения к платформе.

> Правило, которое надо принять целиком: **любая проверка, ответ на которую выводится из содержимого экрана, мертва.** Не «ослаблена», не «рискованна» — мертва, потому что стоимость атаки равна одному нажатию затвора.

Прокторинг эту дыру не закрывает: он фиксирует поведение (взгляд, второе устройство), а не выводимость ответа, требует биометрии и согласий и полностью запрещён в закрытом контуре ОПК. Значит защита должна быть **свойством протокола проверки**, а не надзором за человеком.

---

## 2. Три аксиомы протокола

**A1. В кадре нет ответа.**
Загруженная скрытая правка не отображается никогда: ни диффом, ни кодом, ни номером строки, ни размером совместимого множества. Экран при любом состоянии сессии совпадает **побайтово** для разных скрытых правок. Проверяется дайджестом нормализованного публичного вида (`screen_digest`): при одинаковом коде и разных скрытых гипотезах дайджест один и тот же.

**A2. Ответ добывается взаимодействием.**
Единственный источник информации о скрытой правке — дифференциальный оракул платформы, который на каждый зонд возвращает **ровно один бит**: «поведение на этом входе отличается от оригинала — да/нет». Фотография кадра не содержит ни одного бита ответа; каждый бит стоит отдельного обращения к серверу, которое совершает человек за таймером.

**A3. Ответ без доказательства не считается.**
Оценивается не метка, а вывод. Правильно названная гипотеза **не даёт баллов**, если собранные биты оставляют более одной совместимой гипотезы: это «ОБЭ» — ответ без эвиденции. Угадывание и подсказка снаружи дают 0.

## 3. Конструкция

### 3.1. Множество гипотез вместо одной правки

Платформа берёт **код самого кандидата**, строит по AST 9–15 мутаций (`engine/mutations.py`, детерминированно, без LLM) и отбирает набор `H` из 4–8 гипотез, которые:

- ломают наблюдаемое поведение хотя бы на одном входе из пула зондов;
- **попарно различимы**: у любых двух гипотез вектор бит по пулу различается.

Одна из них выбирается скрытой (`active`) генератором, засеянным сидом сессии. Формулировки всех гипотез публикуются по-человечески («сдвинута граница в условии оптовой скидки», «потерян возврат значения»), а какая именно загружена — нет.

Это принцип Керкгоффса в чистом виде: **весь публичный экран можно отдать любой модели — вердикт всё равно требует не менее ⌈log₂|H|⌉ обращений к оракулу.**

### 3.2. Дифференциальный оракул на один бит

Зонд — это выражение, вызывающее функции решения кандидата, например `order_total(parse_all("Болт;3;12.5"))`. Платформа исполняет его дважды в изолированной песочнице (`engine/sandbox.py`): на оригинале и на скрытом мутанте — и возвращает **только** сравнение подписей, без значений мутанта.

Ограничения зонда (иначе он превращается в канал утечки):

| Проверка | Сообщение при отклонении |
| --- | --- |
| запрещены служебные имена (`__import__`, dunder) | `Служебные имена недоступны` |
| запрещено обращение к атрибутам | `Обращение к атрибутам в зонде запрещено` |
| обязателен вызов функции решения | `Зонд должен вызывать функцию решения` |
| разрешены только публичные имена решения | `Имя open недоступно: зонд вызывает только ваши функции` |
| зонд должен выполняться на оригинале | `Зонд не выполняется на вашем решении: …` |

Отклонённый зонд **не расходует бюджет** — иначе перебор запретов стал бы способом слить биты.

Подписи кодируются так, чтобы сравнение было устойчивым и не протекало наружу:
`V:<repr значения, обрезанный до 120 символов>`, `E:<ИмяИсключения>`, `T:timeout`, `I:<ошибка импорта>`, `?:нет ответа`. Годными считаются только `V:` и `E:`.

### 3.3. Неограниченные прогоны по оригиналу

Прогон собственного кода на любом входе бесплатен и не тратит бюджет зондов (`RUN_BUDGET = 60`): это ноль бит информации о скрытой правке, зато честному кандидату нужно понимать, что его код делает. Дорого стоит только **сравнение** с мутантом.

### 3.4. Двухфазное раскрытие

- **Фаза A (шаг «Локализация»)** — список гипотез закрыт. Кандидат обязан сам найти вход, на котором скрытая правка проявляется. Это убивает офлайновый расчёт таблицы подписей до начала сессии.
- **Фаза B (шаги «Идентификация» и «Ловушка»)** — список гипотез открывается вместе с измерителем улик, но **размер совместимого множества в живом виде не показывается**: он сам по себе является битами ответа.

### 3.5. Каналы ответа — только артефакты кода

Кандидат не выбирает вариант из списка кнопок. Он сдаёт:

1. **различающий вход** (шаг 1);
2. **метку гипотезы плюс собранные биты** (шаг 2);
3. **точную ловушку** (шаг 3) — тест, который **проходит на оригинале и падает на скрытой правке**.

Третий шаг нельзя пройти угадыванием в принципе: чтобы тест падал ровно на загруженной правке, надо знать, какая она, то есть иметь биты оракула. Передача такого артефакта по фотографии требует набрать код руками — это не «нажать нужную кнопку».

## 4. Математика

Пусть `k = |H|`.

- Неопределённость экрана: `screen_entropy_bits = log₂ k`. При `k = 8` это 3 бита, при `k = 5` — 2,322 бита.
- Оракул отдаёт 1 бит за обращение, значит в худшем случае нужно `worst_case_bound = ⌈log₂ k⌉` зондов. Это **нижняя граница для любой стратегии**, включая стратегию внешней модели: информация не берётся из кадра, её нужно купить обращениями.
- Совместимое множество после `m` зондов:
  `H_m = { h ∈ H : [ h(xᵢ) ≠ orig(xᵢ) ] = bᵢ для всех i ≤ m }`.
- Ответ принимается только при `|H_m| = 1` и `h* ∈ H_m`. Иначе — ОБЭ и 0 баллов.
- `bound_instance` — **точная граница конкретного инстанса**: минимальный размер набора зондов из пула, отделяющего `active` от всех остальных гипотез (считается точным перебором по пулу). Он часто меньше `⌈log₂ k⌉`, потому что один удачный зонд может отсечь сразу половину.

**Тонкость, из-за которой протокол пришлось доработать.** `⌈log₂ k⌉` — граница худшего случая, а не гарантия для каждой сессии: везучий кандидат (или модель) может изолировать гипотезу за меньшее число зондов и формально «доказать» ответ дешевле заявленного порога. Поэтому гарантия держится **политикой, а не только арифметикой**: шаг «Идентификация» отклоняет ответ с причиной `not_enough_evidence`, пока сделано меньше `⌈log₂ k⌉` зондов, и такая отклонённая попытка **не расходует попытку ответа**. `bound_instance` публикуется только в итоговом протоколе — живьём он утекал бы битами.

## 5. Стоимость релея

Цикл «сфотографировать → загрузить в модель → получить зонд → набрать и отправить → сфотографировать бит» занимает порядка 40 с при аккуратной работе.

`cycles = min_probes + 2` (зонды плюс локализация и ловушка) ⇒ при `k = 5`: **5 циклов ≈ 200 с при бюджете 900 с**; при `k = 8` — 5–7 циклов и 200–280 с. Сверху ложится набор текста ловушки.

Итог: релей не становится невозможным — он становится **дорогим, заметным и бесполезным как способ сдать быстрее честного кандидата**. Индекс делегирования (раздел 7) при этом уходит в «высокий» по задержке до первого зонда и по вставкам из буфера.

## 6. Протокол сессии

| Шаг | Вес | Бюджет | Что сдаётся |
| --- | --- | --- | --- |
| Локализация | 0,25 | 240 с | вход, на котором скрытая правка проявляется |
| Идентификация | 0,40 | 300 с | метка гипотезы при `\|H_m\| = 1` |
| Ловушка | 0,35 | 360 с | тест: проходит на оригинале, падает на правке |

Бюджеты сессии: `PROBE_BUDGET = 7` зондов, `RUN_BUDGET = 60` прогонов по оригиналу, `SESSION_BUDGET_S = 900`.
Шаги строго последовательны: следующий открывается только после закрытия предыдущего.

Балл локализации падает с числом израсходованных зондов: 1 зонд — 1,0; 2 — 0,9; 3 — 0,75; 4 — 0,6; 5 — 0,5; дальше 0,45.
Провал ловушки: 0,25, если тест хоть что-то убил, иначе 0.

Вердикты: `≥ 0,80` — «Контролирует свой код», `≥ 0,50` — «Контроль шаткий», ниже — «Не контролирует». Понимание считается подтверждённым с 0,70.

## 7. Индекс делегирования (совещательный, не карательный)

0–100 по телеметрии сессии: задержка до первого зонда (> 90 с — +25, > 45 с — +12), вставки из буфера (по 10, не более 30), потери фокуса (≥ 3 — +15, иначе +6), флаг ОБЭ (+30), три и более зондов без различия (+10). Метки: высокий ≥ 55, средний ≥ 25, иначе низкий.

Это **не** основание вердикта и не прокторинг: ни камеры, ни экрана, ни биометрии. Только пояснение к цифрам для работодателя.

## 8. Воспроизводимость и разбор спора

Протокол `pruf.arp.protocol/1` содержит `seed`, `code_fingerprint`, список гипотез, журнал зондов с битами, точную и худшую границы, фактическое число зондов и раскрытую правку с диффом. Любой спор разбирается пересчётом: тот же сид и тот же код дают тот же набор гипотез, ту же скрытую правку и тот же вердикт. Ни одного вызова языковой модели, работает офлайн и в закрытом контуре.

---

## 9. Честные ограничения (публикуем сами)

1. Разогревочная часть релеится по построению — поэтому она весит 0.
2. Модель **может** подсказать хорошие зонды: протокол не защищает от подсказки *стратегии*, он защищает от получения *ответа* из кадра и делает каждый бит платным.
3. Живой компетентный человек рядом обходит любую систему без прокторинга — это верно и для нас, и для конкурентов; мы не обещаем обратного.
4. Защита держится на том, что оракул — единственный канал. Любая утечка (значение мутанта, размер совместимого множества, подсветка «горячей» строки) обнуляет её. Поэтому аудит публичного вида — обязательная часть CI.

## 10. Контракт модуля `engine/arp.py`

Схемы: `pruf.arp/2`, протокол — `pruf.arp.protocol/1`, коллекция хранилища — `arp_sessions`.

**Константы:** `PROBE_BUDGET=7`, `RUN_BUDGET=60`, `SESSION_BUDGET_S=900`, `THRESHOLD_CONTROL=0.80`, `THRESHOLD_SHAKY=0.50`, `CONFIRMED_AT=0.70`, `MAX_EXPR_CHARS=400`, `MAX_EXPR_NODES=180`, `MAX_TRAP_BYTES=8000`, `POOL_LIMIT=10`, `HYPOTHESES_TARGET=8`, `HYPOTHESES_MIN=4`, `PROBE_TIMEOUT=8.0`, `REPR_CAP=120`, `MAX_IDENTIFY_ATTEMPTS=2`, `MAX_TRAP_ATTEMPTS=3`.

**Публичные функции:**

| Функция | Назначение |
| --- | --- |
| `start(code, tests, title, candidate, seed, persist, now)` | собрать сессию: базовый прогон, гипотезы, пул зондов, скрытая правка |
| `load(session_id)` / `tick(session)` | загрузка и пересчёт остатка времени |
| `public_view(session)` | публичный вид без секретов |
| `normalized_public(session)` / `screen_digest(session)` | нормализация и дайджест экрана для проверки A1 |
| `audit_public(session)` | поиск утечек: запрещённые ключи по точному совпадению плюс скан на исходник мутанта |
| `run_original(session, expr)` | прогон по оригиналу, не тратит зонды |
| `probe(session, expr)` | один бит оракула |
| `submit_locate(session, expr)` | шаг 1 |
| `submit_identify(session, hypothesis_id)` | шаг 2 с порогом улик и проверкой `\|H_m\|=1` |
| `check_trap` / `submit_trap(session, tests_src)` | шаг 3: тест на оригинале и на мутанте |
| `telemetry(session, kind)` / `delegation_index(session)` | телеметрия и совещательный индекс |
| `finish(session)` | протокол, вердикт, раскрытие правки |

**Математические помощники:** `entropy_bits`, `min_probes`, `instance_bound(hypotheses, active)`, `worst_case_bound(hypotheses)`, `consistent_set(ids, probe_bits)`, `probe_gain`, `math_note`, `relay_cost`, `verdict_for`.

**Ошибки:** `ArpError(reason, message, status, detail)`; `ProbeRejected` → 422. Коды: `not_enough_evidence` (409), `baseline_failed`, `solution_syntax`, `no_mutations`, `no_probe_pool`, `pool_unusable`, `too_few_hypotheses`, `unknown_hypothesis` (422), `session_finished`, `step_locked`, `step_closed`, `probe_budget`, `run_budget`, `not_differentiating`, `wrong_hypothesis`, `trap_fails_on_original` (409), `trap_empty`, `trap_too_large`, `trap_syntax`, `trap_no_tests`, `unknown_telemetry` (422), `unknown_step` (404).

**Запрещённые в публичном виде ключи** (точное совпадение, без подстрок — иначе ложные срабатывания вида `weights.witness`): `secret`, `active`, `probe_bits`, `signature_cache`, `pool`, `base_signatures`, `correct`, `answer`, `mutant`, `pool_bits`.

## 11. Прогон прототипа 15.09.2026

Сценарии смоук-теста `tools/smoke_arp.py` и результат:

| Сценарий | Результат |
| --- | --- |
| 1. Сборка сессии: ≥ 4 гипотез, попарная различимость, пустой аудит, закрытый список | OK (5 гипотез, порог 3 зонда, энтропия 2,322 бита, пул 10, сборка 0,3 с) |
| 2. Аксиома A1: 5 сидов | OK — скрытые правки разные (`M04`, `M12`, `M15`), дайджест экрана один (`052a5930397aeabd`) |
| 3. Атака фотографией: без зондов | OK — совместимы все 5 гипотез; релей 5 циклов ≈ 200 с при бюджете 900 с |
| 4. ОБЭ: верный ответ без улик | 3 расхождения — см. ниже |
| 5. Честная сессия целиком | OK — прогон по оригиналу зондов не тратит, зонды оставили ровно `M04`, ловушка сработала (разрешающая сила 0,2, точная), аудит чист, вердикт «Контролирует свой код (100 %)», зондов 3 ≥ порога 3 |
| 6. Воспроизводимость по сиду | OK — тот же сид даёт ту же скрытую правку и тот же набор гипотез |
| 7. Негодные зонды | OK — все четыре отклонены, бюджет не израсходован |

**Итог: 30 OK, 3 FAIL.**

Причина трёх расхождений — дефект сценария, а не протокола: тест добирал порог улик «наименее информативными» зондами по жадной эвристике, но она не гарантирует сохранения второй совместимой гипотезы, и к моменту ответа совместимой осталась ровно одна. То есть построить ситуацию ОБЭ у теста не получилось, а не «гейт пропустил угадывание».

**Исправление сценария (детерминированное):** для каждой гипотезы-напарника `p ≠ active` собрать индексы пула, где биты `p` и `active` совпадают; если таких индексов не меньше порога и среди них есть хотя бы один с битом 1 (он пойдёт на локализацию) — потратить порог именно на них. Тогда `p` остаётся совместимой по построению, `|H_m| ≥ 2`, и ответ с верной меткой обязан получить 0 и флаг ОБЭ. Если у сида такой пары нет, перебрать несколько сидов.
